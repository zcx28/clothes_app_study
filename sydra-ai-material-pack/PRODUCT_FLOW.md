# 页面、状态与交互规格

## 一级结构

底部导航固定为：首页、选购、购物车、我的。

## 核心可验证路径

1. 启动 → 登录协议状态 → 登录中/失败或成功 → 首页。
2. 首页 → 选购 → 商品列表模式 → 分类 → 商品列表 → 商品详情 → 加入购物车。
3. 选购 → 配置器模式 → 系列 → 尺码 → 配置步骤 1–4 → 购物车。
4. 购物车空、未勾选、全选，以及 V2 的确认订单、选地址和本地支付状态。
5. 我的 → 订单各 Tab → 详情、修改地址、物流、退货、退款状态。
6. 退货订单号 → 原因 → 其他原因及凭证 → 提交/售后列表与进度。
7. 地址列表 → 新增地址 → 校验、保存中、成功。
8. 我的 → 会员/权益、帮助/文章、客服/聊天失败与重试成功。

## Route 与状态矩阵

| Route / 状态域 | 入口 | 用户操作与目标 | Android 返回 | 关键状态/数据 |
|---|---|---|---|---|
| Splash | 冷启动 | 自动进入 Login；已有本地登录态可到 Home | 退出 App | 启动完成 |
| Login | Splash | 勾协议、查看协议弹层、登录、失败重试 | 弹层先关闭；失败回默认；成功后不回登录中 | 协议未选/已选、登录中、失败、成功 |
| Home | 登录成功/底栏 | 探索 CTA 进入 ShopMode；底栏切换 | 根页面返回退出 | V2 明确 CTA 去选购 |
| ShopMode | 首页/底栏选购 | 选择 Configurator 或 Products List | 返回 Home/根目的地 | 模式选择 |
| Series | 配置器模式 | 选择系列进入 Size | 返回 ShopMode | 系列选择 |
| Size | Series | 选择 S/M/L 后继续 | 返回 Series | 未选、已选、错误、中断恢复；未选禁用 |
| Configurator | Size | 四步选择，完成后加入购物车 | 逐步返回并保留选择 | 步骤 3 未选/已选、步骤 4 待确认/可完成是同 Route 状态 |
| Category | 商品列表模式 | 切换服饰/配件 Tab；选择 ACT 等分类 | 返回 ShopMode | Tab 是状态，不复制页面 |
| ProductList | Category/Search | 选择商品进入详情；筛选为本地 UI 状态 | 返回调用页 | ACT 列表 |
| ProductDetail | ProductList/Search | 选择尺码；加入购物车 | 返回调用页 | 未选尺码禁用加入；内容可滚动 |
| Search | 多个搜索入口 | 输入、提交、选结果、重试 | 返回原调用页并保留来源 | 默认、加载、结果、空、错误 |
| Cart | 底栏/加入商品 | 勾选、全选、结算 | 底栏根切换 | 空、未选、全选；V1/V2 结算条件冲突见下文 |
| Checkout | Cart | 查看商品/金额、选择地址、去支付 | 返回保留购物车和选择 | 默认、无地址、地址选择 |
| AddressList(mode) | Profile/Checkout/Order | 管理、结算选择、订单修改 | 回到对应来源 | MANAGE、CHECKOUT、ORDER_CHANGE |
| Payment | Checkout/待付款 | 选微信/支付宝、支付、返回 | 返回先显示放弃支付确认 | 方式选择、支付中、放弃弹层 |
| PaymentResult | Payment | 成功到待发货；失败重试或稍后支付 | 不回支付中 | 成功清结算商品；失败/放弃保留待付款 |
| Profile | 底栏我的 | 订单快捷入口、地址、会员、帮助、客服 | 根页面返回退出 | 个人中心内容 |
| Orders | Profile/支付结果 | 切 Tab、打开菜单、详情、付款、取消、物流、退货 | 返回 Profile | 待付款、待发货、已发货、已完成、售后；Tab/菜单是状态 |
| CancelOrder | 待付款订单 | 二次确认、提交、失败重试 | 危险操作先关闭确认 | 确认、提交中、成功、失败 |
| OrderDetail | Orders | 查看只读订单信息 | 返回 Orders 原 Tab | 商品、金额、地址快照 |
| Logistics | 已发货订单 | 查看物流时间线 | 返回 Orders | 运输节点 |
| ReturnOrder | 已发货/已完成 | 输入非空订单号继续 | 返回 Orders | 空/已填；非空启用 |
| ReturnReason | ReturnOrder | 选择原因；普通原因提交，其他进入凭证 | 返回 ReturnOrder | 原因未选禁用 |
| ReturnEvidence | 其他原因 | 填问题、添加本地凭证入口、提交 | 返回原因页 | 描述非空启用；真实上传协议缺失 |
| AfterSales | 提交后/订单售后 | 查看提交、退款中、完成或拒绝 | 返回售后列表 | Submitted、Refunding、Completed、Rejected |
| AddressAdd | 地址列表 | 输入、校验、保存 | 返回调用列表 | 默认、校验错误、保存中、成功；保存失败需保留输入 |
| Member/Benefits | Profile | 查看会员和权益 | 逐级返回 Profile | 只读内容 |
| Help/Article | Profile/权益 | 浏览帮助和文章 | 逐级返回 | 只读内容 |
| Support/Chat | Profile/文章/拒绝态 | 输入消息；失败保留输入并重试 | 返回客服，关闭保留会话 | 默认、发送中、失败、成功 |

## 状态建模规则

- Configurator 步骤 3 和 4 不拆成多条 Route。
- Category Tab、Cart 选择、Order Tab、Search 状态、登录状态、弹层和提交结果都用同页状态建模。
- 支付成功、取消成功等成功终点应清理不能返回的中间页。
- 系统返回与顶部返回遵循同一契约；弹层优先关闭。
- 页面重建应恢复购物车、配置选择、登录结果、订单和表单中需要保留的数据。

## 证据阶段冲突

1. 首页 CTA：早期文字曾将目标视为缺失主题详情；V2 Figma 节点 `114:1839` 明确连接选购，因此采用“进入选购”，不虚构主题详情页。
2. 购物车结算：V1 截图显示“有商品且全选才启用”；V2 原型允许有商品进入结算，并用无地址/补地址分支继续。若实现 V2 全流程，采用 V2；若只复刻 V1，必须明确标记版本，不可混用测试断言。
3. V1 缺少登录失败、支付、搜索、取消、退款进度和会员等页面；V2 导出为这些原型状态提供视觉证据，但仍不提供真实 SDK、API 或服务器。
